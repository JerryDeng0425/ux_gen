# Step 03：页面快捷键捕获桥

## 目标

让用户在页面保持焦点时按 `Ctrl+Shift+Y` 捕获弹窗、菜单等瞬时状态，并使快捷键与终端命令复用同一捕获入口。

## 前置条件

- Step 02 的 browser session 和终端链路稳定。
- 已定义捕获状态和失败重试语义。

## 实施任务

1. 用 `browserContext.exposeBinding()` 暴露 Node 接收函数。
2. 用 `addInitScript()` 在首次加载及后续导航前注册快捷键。
3. 在 `keydown` 中记录 `requestedAt`，同步调用页面序列化入口。
4. 序列化完成后才异步将冻结 payload 发送给 Node。
5. 为单页增加捕获互斥锁和重复触发提示。
6. 终端 `capture` 通过 `page.evaluate()` 调用相同序列化入口。
7. 检测新标签、页面关闭、导航中和快捷键冲突。
8. 记录快捷键触发到同步克隆开始的延迟。

## 交付物

- Capture Bridge。
- 页面注入脚本。
- 快捷键/终端共用的捕获接口和集成测试。

## 可验收项

| ID | 验证方法 | 通过标准 | 验收证据 |
| --- | --- | --- | --- |
| AC-03-01 | 打开弹窗并按快捷键 | 弹窗保持打开且被捕获，不需要切换到终端 | HTML、参考截图 |
| AC-03-02 | SPA 路由切换后再次按快捷键 | 新页面仍能捕获，监听器不重复注册 | 两次捕获日志 |
| AC-03-03 | 快速连续按快捷键 5 次 | 同时最多一个 capture；其余得到明确 busy 反馈 | 并发测试日志 |
| AC-03-04 | 分别使用快捷键和终端捕获同一 fixture | 两者走相同 serializer 版本和 metadata schema | payload 对比报告 |
| AC-03-05 | 捕获过程中触发导航 | 不生成半文件，结果失败可重试，CLI 不崩溃 | 故障注入报告 |
| AC-03-06 | 页面打开新标签 | CLI 暂停或提示选择，不静默捕获错误页面 | 多页测试记录 |
| AC-03-07 | 检查业务 DOM | 注入脚本未增加按钮、toast、属性或可见节点 | DOM diff |
| AC-03-08 | 重复测量触发延迟 | 生成 p50/p95 数据，p95 目标不高于 200 ms | 性能原始数据 |

## 完成判定

快捷键能跨路由稳定工作，瞬时 UI 不因切焦丢失，所有触发入口共享同一核心逻辑。
