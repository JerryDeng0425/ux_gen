# Step 07：实现 Vuestic 场景工作流

## 目标

把 PRD 的 K01–K04 转换为清晰、版本化、可执行和可验证的人工操作任务。

## 前置条件

- Step 06 已证明工具在本地 fixture 上正确。
- 当前环境可访问 Vuestic Admin。
- 公开 Demo 的变化不能改变核心能力验收语义。

## 实施任务

1. 侦察 Dashboard、Users、编辑弹窗、Preferences/Settings 的当前页面结构。
2. 为每个关键点选择稳定语义 selector，并记录候选 fallback。
3. 编写 `scenarios/vuestic.json`：版本、入口、步骤说明、断言、脱敏 selector、视觉 mask。
4. CLI 显示当前关键点、用户需要完成的动作和到达标准。
5. 捕获前做非侵入式断言；失败时允许修正、重试或带原因跳过。
6. 验证主题、表单值、弹窗遮罩、当前路由和导航选中状态。
7. 若公开 Demo 改版，按 PRD 使用等价 Projects 编辑弹窗并提升场景版本。

## 交付物

- `scenarios/vuestic.json`。
- selector 侦察记录和场景版本说明。
- K01–K04 的一次人工基线运行。

## 可验收项

| ID | 验证方法 | 通过标准 | 验收证据 |
| --- | --- | --- | --- |
| AC-07-01 | 新用户仅按 CLI 提示执行 K01 | 能到达 Dashboard 状态并成功捕获 | 操作记录、K01 产物 |
| AC-07-02 | 在 Users 输入筛选词并排序后捕获 K02 | 输入值、结果列表、排序和导航状态满足断言 | K02 HTML/JSON/PNG |
| AC-07-03 | 打开编辑弹窗、填写两个字段但不提交后捕获 K03 | 弹窗、遮罩和两个当前值均存在 | K03 产物及断言 |
| AC-07-04 | 切换主题或布局后捕获 K04 | 控件选中状态、主题 class 和页面内容一致 | K04 产物及断言 |
| AC-07-05 | 故意未完成当前操作就捕获 | CLI 明确指出未满足断言，并允许返回修正 | 负向操作日志 |
| AC-07-06 | 执行 `skip K03 <reason>` | summary 记录原因，其他关键点仍可完成 | run summary |
| AC-07-07 | 场景 selector 失效 | 输出失败 selector、页面 URL 和更新提示，不误判成功 | 失效模拟记录 |
| AC-07-08 | 完成整套流程 | K01–K04 各有 HTML/PNG/JSON，运行有 summary | 完整目录清单 |

## 完成判定

未参与开发的操作人员可以仅凭终端提示完成 K01–K04；关键状态都能由机器断言，而非只靠截图人工判断。
