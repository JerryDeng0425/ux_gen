## 目标

证明业务分析师无需额外工具或 Skill，只用一条自然语言需求即可同时修改已有页面并新增一个完整页面；Codex 直接编辑当前原型、自动验证并重新输出离线 ZIP。

## 验收需求模板

使用一条具有明确业务语义的需求，至少包含：

1. 在已有列表页新增查询条件、表格列或编辑字段之一，并与当前数据/语料一致；
2. 新增一个相关业务页面，接入菜单、Hash route、面包屑和必要交互。

实际需求由验收时的业务分析师以自然语言提出，不固化成录制流程或代码生成 schema。

## 实施范围

1. Codex 直接读取当前原型、相关基线和按需 Element Plus 参考。
2. 后续普通修改不要求修改前确认；仅在需求存在会实质改变结果的歧义时请求方向。
3. 新页面自动选择结构和业务最接近的基线页面作为风格、字段和语料参考。
4. 直接修改 `prototype/`，同步更新 route/menu/breadcrumb、内存数据和关键交互测试。
5. 运行 Step 31 全部自动验证和 Step 32 离线打包。
6. 完成后向用户提供代码 diff 摘要、受影响页面、验证结果和新 ZIP 路径。
7. 不创建页面 Agent、HTML→Vue 工具或新工作流 Skill，不自动 Git commit。
8. 修改前后比较基线 hash，证明录制 HTML 未被改写。

## 预计产物

- 修改后的现有页面和一个新增页面；
- 更新后的菜单、route、breadcrumb、交互和测试；
- 新的验证报告与离线 ZIP；
- 面向用户的 diff/结果摘要。

## 失败与回退边界

- 自动验证失败时继续修复；若仅剩业务歧义无法自动解决，应明确报告并保留最后一个验证通过的 ZIP。
- 不允许以只生成静态 HTML 页面代替 Vue 原型页面。

## 完成定义

一条自然语言需求完整落地为“修改旧页 + 新增页面”，所有自动检查和离线交付重新通过，且无额外 Skill、自动提交或基线改写。
