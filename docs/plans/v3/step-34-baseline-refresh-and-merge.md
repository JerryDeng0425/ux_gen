## 目标

当原系统新版本上线并重新录制同名页面时，只更新只读 HTML 基线；Codex 对比新基线和当前原型，先说明影响与冲突，用户确认后才合并，同时保留已经确认的新需求改动。

## 实施范围

1. 仅通过录制 Skill 对至少一个同名页面再次 capture；验证 `baseline/pages/<页面>.html` 被原子更新。
2. 重录完成时不得自动修改 `prototype/`、验证脚本或当前交付 ZIP。
3. 在自然语言会话中由 Codex 直接比较：
   - 旧/新基线的页面结构、字段、语料、导航和状态；
   - 新基线与当前原型的差异；
   - 当前原型中不来自基线、但已经确认的新需求改动。
4. 输出受影响页面、建议变更、潜在冲突、应保留的新需求和无法判断事项。
5. 用户明确确认合并前，记录 `prototype/` hash 并保持零变化；取消时原型和 ZIP 不变。
6. 确认后只修改受影响的原型页面及相关测试，不覆盖已确认的新需求，随后运行 Step 31/32。
7. 不开发自动 merge engine、版本中心、页面 Agent 或新的 Skill；这是 Codex 的自然语言协作流程。

## 预计产物

- 更新后的同名 HTML 基线；
- 对话中的影响/冲突/保留项说明；
- 用户确认记录；
- 确认后的原型 diff、新验证报告和 ZIP（若用户确认合并）。

## 失败与回退边界

- 用户未确认或取消时，不允许修改原型。
- 合并失败时恢复到最近一次验证通过的原型/ZIP，但保留新基线作为事实输入；不得反向修改基线以适配原型。

## 完成定义

新基线可以独立更新、先分析后确认、再受控合并；已有新需求得到保护，取消或失败都不会破坏当前可用原型。
